1 Introduction 
 
The EdgePoint Industrial creates a data string using the JavaScript Object Notation (JSON) format. This 
is a data interchange format that is easy for humans to understand and for machines to parse and 
generate. This format has become extremely popular for Internet of Things (IoT) applications with many 
software packages including support for the format. More information can be found at 
https://www.json.org/json-en.html. 
 
The EdgePoint Industrial uses the MQTT messaging protocol for communications between the client and 
server. This is a publish – subscribe network protocol for logically connecting remote devices to a server. 
Data from devices is published to a specific Topic managed by an MQTT Broker on a cloud server. MQTT 
Clients can subscribe to the Topic to receive the data when it is published. Login to the broker and 
permissions settings for the Topics ensure that specific Clients can only access specific Topics. 
 
 
2 MQTT Topics 
 
The messages from the remote device to the MQTT broker are sent to the following topic: 
 
 /devices/<serialnum>/messages/events/ 
 
Messages from the MQTT broker to the remote device are posted to the following topic: 
 
 /devices/<serialnum>/messages/devicebound/ 
 
Messages from an external controller that is connected to the Nexus Industrial are posted to the following 
topic: 
 
 /devices/<serialnum>/messages/events/module 
 
For each of the topics, the <serialnum> field is the serial number of the Nexus Industrial. The serial 
number of an external controller or device is contained within the posted message, but not in the topic.

3.2 Update the Device Configuration File 
 
The following command is used to update the device configurations remotely. This is posted to the 
“devicebound” topic. 
 
{"file": { <new settings> }} 
 
The configuration settings include the following 
 
throttle – The interval in seconds for the transmission of the device data to the broker 
addr – The MQTT broker address 
port – The MQTT broker port number 
user – The MQTT broker user name 
password – The MQTT broker password 
 
 
3.3 Update the Modbus Configuration 
 
The following command is used to update the Modbus configuration in the device. It is posted to the 
“devicebound” topic. 
 
 {"modbus": [ 
   { 
    "name": "<logical name>", 
    "client": { 
     "protocol": "rtu", 
     "address": <controller address>, 
     "baud": <baudrate>, 
     "sn": "<serial number>" 
    }, 
    "registers": [ <register list> ] 
   } 
  ] 
 } 
 
 
modbus – Defines an external Modbus device interface 
 
name – A logical name for the external controller 
poll – The interval in seconds to interrogate the external controller 
throttle – The interval in seconds for transmission of the external Modbus data to the broker 
client – A structure containing the Modbus communications configuration 
client.protocol – The Modbus protocol to be used – RTU or TCP 
client.address – The address of the external controller

values, so the device can read the registers on a quick interval then report the aggregated values to 
the server on a longer interval.

4 Device to Broker / Server Data Structures 
 
The JSON messages sent by the EdgePoint RTU to the broker begin with a left brace ({) and end with a 
right brace (}). Within the braces are a series of Names followed by a colon (:) and then a Value. Each 
name / value pair are separated by a comma (,). A value can also be an array of Name / Value pairs. An 
array 
 
The Names supported by the EdgePoint RTU are all strings in double quotes (“ “). Values can be a string 
in double quotes, or a number, or true or false or null.  
 
The following table outlines the Names and Values sent by the EdgePoint RTU to the broker. 
 
Name Value Description Data Type 
“10” <serialnum>, Serial Number int 
“12” <application version>, Software Application Version string 
“appname” <application Name>, Software Application Name string 
“variant” <variant>, Hardware Variant int 
“mac” <MAC Address>, Device MAC Address string 
“inputs” <input object>, Device Input Control and Monitoring array 
"outputs" <output object>, Device Output Control and Monitoring array 
“tz” <time zone>, Time Zone Offset int 
“dst” <daylight savings time> Daylight Savings Time Indicator Int

7 Update MQTT Broker on the EdgePoint Industrial 
 
This section describes how to change the MQTT broker on the EdgePoint Industrial directly, without 
having to go through the default broker. 
 
 
7.1 Wi-Fi Login 
 
The gateway automatically starts broadcasting Wi-Fi once it boots up. To connect to it, look for the 
following Wi-Fi network: 
 
SSID: NS-nnnn 
Password: iotpoint 
 
The "nnnn" part of the SSID are the last few characters in the device's MAC address. The SSID and 
password can be changed by logging into the LUCI interface on the gateway.
